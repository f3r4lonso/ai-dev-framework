# TASK PROMPT — Incorporate the Ollama CLI as a Local Model Runtime in the Shared Infrastructure

Status: active

The user launching this prompt approves Phases 0–1 only (read-only). Every later step needs the gates in §4.
Do not run this task at the same time as another task that edits `docs/` or `WORKSHOP-CONTEXT.md`; if one is
running, stop and ask.

## 1. Role and mission

You are an **AI infrastructure engineer** responsible for adding a new provider to the shared infrastructure without
weakening its security or documentation contracts. You:

1. install the Ollama CLI and a small, approved set of local models on the maintainer's Windows laptop;
2. verify that they run on the GPU and that the server is reachable only from this machine;
3. register Ollama as a provider following `docs/ai-architecture.md` §8, so any person or client in the workspace
   can find how to use it, what it is for, and what it must never be used for;
4. optionally evaluate Ollama as a backend for Claude Code / Codex CLI and record the result honestly;
5. hand over a measured, labelled result.

Ollama is a **local model runtime**, not a coding client: it does not read `AGENTS.md`, skills or agents. The
integration documents and verifies the runtime. It does not build adapters for it unless Phase 1 shows a documented
mechanism that needs one.

## 2. Current state and decided direction (verified 2026-10-19; re-check in Phase 0)

- **Repository:** `%USERPROFILE%\workshop\infra`, one **public** git repository with a whitelist `.gitignore`.
  Everything committed is published. Confirm the root with `git rev-parse --show-toplevel`.
- **Machine:** Windows 11 Pro; NVIDIA laptop GPU with 8 GB VRAM; 16 GB RAM. Ollama is **not installed**
  (`ollama` not found).
- **Ollama facts (Documented, docs.ollama.com, checked 2026-10-19; re-check in Phase 1):**
  - Windows installer `OllamaSetup.exe`, user-level install without admin rights; needs Windows 10 22H2+ and NVIDIA
    driver 551.61+. Model folder can be moved with `OLLAMA_MODELS`. Ollama itself is MIT-licensed.
  - Local API at `http://localhost:11434`: native `/api/chat`; OpenAI-compatible `/v1/` (chat/completions,
    responses, embeddings, models) that accepts any placeholder API key.
  - Default context is 4k tokens on GPUs under 24 GB VRAM. Change it with `OLLAMA_CONTEXT_LENGTH` or the app
    setting, and check it with `ollama ps` (CONTEXT and PROCESSOR columns; the target is 100% GPU). Coding tools need
    at least 64k context.
  - `ollama launch claude` and `ollama launch codex` exist (Codex also has `codex --oss`;
    `ollama launch codex --restore` removes the profile). The manual Claude Code setup uses the environment variables
    `ANTHROPIC_BASE_URL=http://localhost:11434`, `ANTHROPIC_AUTH_TOKEN=ollama`, `ANTHROPIC_API_KEY=""`.
  - **Data leaves the machine** with models tagged `:cloud`, with `ollama signin`, and with Ollama web search: all of
    them talk to ollama.com.
- **Model candidates (license to verify in Phase 1):**
  - `qwen3.5:4b`: 3.3–4.0 GB, the proposed default.
  - `qwen3.5:9b`: 6.6–7.6 GB, tight on 8 GB VRAM, optional.
  - one embedding model, such as `embeddinggemma`.
  - The qwen3.5 library page does not show a license, so it must be checked.
- **Decided direction (user-reviewed design, do not reopen):**
  - Local models are for **private, repetitive text work**: summaries, extraction, tagging, translation, local
    search.
  - They are **not** a replacement for cloud coding agents on this laptop: with 8 GB VRAM a 64k context spills to the
    CPU.
- **Security rules (hard):**
  - Private data goes only to local models: no `:cloud` models, no `ollama signin`, no web search.
  - Never set `OLLAMA_HOST` to `0.0.0.0` or any non-loopback address, and never open port 11434: the API has no
    authentication.
  - Any `OLLAMA_API_KEY` appears only as an environment-variable name, is added to `SECURITY.md` and is considered
    in the gitleaks review (a rule only if the key format is documented).
  - Ollama is **never** used in the trading path of Trading-app (signals, orders, risk).
- **Requires verification in Phase 1:**
  - whether the Windows app autostarts at login and auto-updates;
  - whether it offers a "expose to network" setting;
  - whether `%USERPROFILE%\.ollama\` holds a private key or other identity files (treat it as a credential store
    until proven otherwise: never open its files);
  - what `ollama launch claude|codex` writes to client configuration.

## 3. Scope

- verifying it from the CLI and the local API;

**Out of scope:**
- changes to any application repository;
- new agents or skills;
- adapters generated by `scripts/codex-adapter.py`;

   `risk.py`.
